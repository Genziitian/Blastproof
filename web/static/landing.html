01 · Recall

Memory is found by walking the dependency graph.

When payments-gw alerts, the agent walks to postgres-payments, a datastore of the same kind as postgres-orders, where a playbook was learned. A text search for “slow responses” would not have found it.

Recall
02 · Check

Nothing is trusted until live evidence agrees.

Every playbook carries checks. The agent reads the observed value for each one before it trusts the playbook. In s04 every check holds. In s05 the same playbook is recalled, but checkout-api was just deployed, so it is ruled out and its trust is left alone.

03 · Coordinate

Kill an agent. Its work carries on.

Agents claim tasks with a lease and write a checkpoint after every step. When an investigator is killed, its lease drains over six seconds. The other claims the task, the epoch moves from e1 to e2, and the work resumes at the next step, not from scratch. The dead one can never write again.

04 · Act

One page, the way the engineer asked.

05 · Learn

Trust is earned per playbook, and lost the same way.

Engineer preferences are versioned facts. What the engineer approved supersedes what the agent assumed. Both stay on record.

Memory survives a database restart.

Restart FalkorDB mid-demo. Mission control dims, reconnects, and reads everything back from the graph.

Under the hood

One graph. Every step is a query you can read.

Services, playbooks, incidents, leases, checkpoints and conversations all live in FalkorDB. Every panel in mission control has a query button that shows the Cypher behind it. Every step is stored, so any incident can be replayed.
